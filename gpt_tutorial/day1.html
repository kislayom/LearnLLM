🧠 Train an LLM from Scratch — Day 1

Foundations & the attention mechanism — theory and the maths behind it.

Every jargon term links to its definition in the glossary. The runnable code is at the bottom.

1. The big picture

A large language model is one function that estimates P( next token | all previous tokens ) Using the chain rule of probability, that single conditional is enough to score or generate any text. This makes GPT an autoregressive model. Everything else — embeddings, attention, the loss — exists to make that one prediction accurate.

2. Day-1 concept map

#ConceptPlain EnglishThe mathsWhy it matters
1 Autoregressive LM Predict the next token from the previous ones; repeat to generate. P(x₁..ₜ)=Π P(xᵢ|x₁..ᵢ₋₁) via the chain rule. Turns "model a whole sentence" into one repeatable prediction.
2 Tokenization Map text to integer ids from a fixed vocabulary. text → ids ∈ {0 … |V|−1} Models do maths on numbers, not letters. Granularity (char vs BPE) trades vocab size against sequence length.
3 Embeddings Each token id becomes a learned vector. token i → row E[i] of matrix E (|V|×d); same as one‑hot · E. Gives tokens geometry/meaning that gradient descent discovers.
4 Logits → softmax Model outputs raw scores; softmax turns them into probabilities. softmax(z)ⱼ = exp(zⱼ) / Σₖ exp(zₖ) Produces a valid probability distribution over the vocabulary (≥0, sums to 1).
5 Cross-entropy loss Penalty for being confident and wrong; small when right. L = −log P(correct token) (= negative log-likelihood) The single number we minimize. Starts near log|V| for a random model.
6 Gradient descent + backprop Nudge every parameter in the direction that lowers the loss. θ ← θ − η · ∇θ L How the model actually learns. Adam is the smarter step rule we use.
7 Self-attention Each token gathers info from the tokens it finds relevant. Attention(Q,K,V) = softmax(Q·Kᵀ / √d) · V The core mechanism of the transformer; lets context flow between tokens.
8 Query / Key / Value Q = what I want, K = what each token offers, V = the info handed over. q=x·W_Q, k=x·W_K, v=x·W_V; score = q·k. The "search" that decides where each token looks.
9 Causal mask A token may only look at the past, never the future. set scoreᵢⱼ = −∞ for j > i before softmax. Without it the model could "cheat" by seeing the answer.
10 Quadratic cost Every token compares with every token → a T×T grid. cost ∝ T² (2× longer ⇒ 4× work). Why long context is expensive; motivates sparse/FlashAttention.

3. Questions I asked (and the answers)

#My questionShort answer
1 Why don't we tokenize letter-by-letter? We can (and will, for learning — tiny vocab, fully transparent). But at scale it makes sequences ~5× longer ⇒ ~25× more attention compute (quadratic), wastes capacity on spelling, and fits less real text per context. BPE is the compromise.
2 Why is attention "quadratic"? Cost grows like T² (the square of the length): T tokens each comparing against T tokens = a T×T grid. Double T ⇒ 4× work; 10× ⇒ 100×.
3 Can we optimise it / skip some checks? Yes. Causal masking already drops ~half. Beyond that: sparse/local attention (O(T·w)), linear attention (O(T), drops softmax sharpness), FlashAttention (same maths, faster memory) and the KV cache (don't redo past work when generating). Trade-off: exact-but-quadratic vs approximate-but-cheap.
4 What is softmax(Q·Kᵀ)? The dot products Q·Kᵀ form a T×T grid of query–key similarity scores; softmax on each row turns them into attention weights (≥0, sum to 1) saying how much each token attends to every other. Divide by √d to keep it trainable, then multiply by V to blend the information.

4. The attention formula, decoded

The one line at the centre of every transformer:

Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V
  • Q·Kᵀ — every dot product of query·key → a T×T grid of raw similarity scores (logits).
  • / √d — scale down so large dot products don't saturate the next step.
  • softmax (per row) — turn each row of scores into attention weights that sum to 1.
  • · V — use those weights to take a weighted average of the value vectors → each token's context-aware output.
Worked example: query q₂=[1,0], keys k₁=[1,0], k₂=[0.2,0.9] → scores [1.0, 0.2] → softmax → [0.69, 0.31]. Token 2 pays 69% attention to token 1.

5. Glossary & references

Autoregressive model
A model that predicts the next value from its own previous values; for text, the next token from previous tokens.
Ref: Wikipedia — Autoregressive model
Chain rule (probability)
The exact factorization P(x₁..ₜ)=Π P(xᵢ|x₁..ᵢ₋₁) that lets one next-token model score whole sequences.
Ref: Wikipedia — Chain rule (probability)
Tokenization
Splitting text into units (characters or subwords) and mapping each to an integer id.
Ref: tiktoken (GPT tokenizer)
Vocabulary (|V|)
The fixed set of all possible tokens. Size |V| sets the embedding-table and output-layer width.
Byte-Pair Encoding (BPE)
Subword tokenizer: start from characters and greedily merge the most frequent adjacent pairs until a target vocab size. Common words become one token; rare words split; no out-of-vocabulary.
Ref: Wikipedia — Byte-pair encoding · Sennrich et al. 2015
Embedding
A learned vector representing a token (a row of the embedding matrix E, shape |V|×d). Looking it up equals multiplying a one-hot vector by E.
Ref: Wikipedia — Word embedding
Logits
The model's raw, unbounded output scores before softmax (one per vocabulary token).
Ref: Wikipedia — Logit
Softmax
Turns a vector of real scores into a probability distribution: softmax(z)ⱼ = exp(zⱼ) / Σₖ exp(zₖ). All outputs are ≥0 and sum to 1; the exp sharpens differences so the model can focus.
Ref: Wikipedia — Softmax function
Cross-entropy loss
L = −Σ yⱼ log pⱼ = −log p(correct). The training objective; minimizing it = maximum likelihood. Perplexity = exp(L).
Ref: Wikipedia — Cross-entropy
Maximum likelihood / log-likelihood
Choose parameters that make the observed text most probable; equivalently minimize the negative log-likelihood.
Ref: Wikipedia — MLE
Perplexity
exp(loss) — roughly "how many tokens the model is confused between." 1 = perfect, |V| = random.
Ref: Wikipedia — Perplexity
Gradient descent
Iteratively step parameters opposite the gradient of the loss: θ ← θ − η·∇θL. η is the learning rate.
Ref: Wikipedia — Gradient descent
Backpropagation
The chain rule of calculus applied backward through the network to compute every parameter's gradient in ~one pass. PyTorch's loss.backward().
Ref: Wikipedia — Backpropagation
Adam / AdamW
An optimizer that adapts the step size per parameter using running averages of gradients (momentum) and their magnitudes; AdamW decouples weight decay.
Ref: Kingma & Ba 2014 · Loshchilov & Hutter 2017 (AdamW)
Self-attention
Mechanism where each token computes a weighted sum of all (past) tokens' values, weighted by query–key similarity. softmax(Q·Kᵀ/√d)·V.
Ref: Vaswani et al. 2017 — "Attention Is All You Need"
Query, Key, Value (Q, K, V)
Three learned linear projections of each token: Query = what I'm looking for, Key = what I offer, Value = the information I pass on when attended to.
Ref: Vaswani et al. 2017, §3.2
Dot product
a·b = Σ aᵢbᵢ — a single number measuring how aligned two vectors are; the similarity score in attention.
Ref: Wikipedia — Dot product
Scaling by √d
Dividing the scores by √(head dim) keeps their variance ~1 so softmax doesn't saturate (which would kill gradients). The "scaled" in scaled dot-product attention.
Ref: Vaswani et al. 2017, §3.2.1
Causal mask
Setting future positions' scores to −∞ before softmax so each token attends only to itself and the past. Required for next-token training.
Quadratic cost (O(T²))
Attention compares every token with every token, so compute/memory grow with the square of the sequence length T.
Ref: Wikipedia — Time complexity
Sparse / local attention
Only attend to a subset of tokens (e.g. a sliding window of size w, plus a few global tokens) → O(T·w). Risks missing genuine long-range links.
Ref: Longformer · BigBird
Linear attention
Reformulate (drop/approximate softmax) so the T×T matrix is never built → O(T). Loses some of softmax's sharp focus.
Ref: Linformer · Performer
FlashAttention
Computes exact attention (still O(T²) maths) but tiles the work in fast on-chip memory, avoiding the slow read/write of the full T×T matrix → much faster, less memory.
Ref: Dao et al. 2022
KV cache
During generation, cache past tokens' keys/values so each new token costs O(T) instead of recomputing everything. Why chatbots stream quickly.

7. The code (runnable)

Two files live next to this page: get_data.py (creates input.txt) and train.py (the model). Run:

cd gpt_tutorial
pip install torch          # CPU build is fine
python get_data.py        # downloads tiny Shakespeare (offline fallback included)
python train.py           # trains, prints loss, then generates a sample

What to watch: the printed initial loss should be ≈ log(|V|) (≈ 4.17 for ~65 chars). It should fall steadily, and the generated text should drift from gibberish toward Shakespeare-ish English. That progression is the lesson.

train.py

import os
import torch
import torch.nn as nn
from torch.nn import functional as F

# ---- Hyperparameters: the "knobs" you'll experiment with ----
batch_size = 32          # sequences processed in parallel
block_size = 64          # context length T (max tokens of history)
max_iters = 3000         # training steps
eval_interval = 300
learning_rate = 3e-4     # step size eta
eval_iters = 100
n_embd = 128             # embedding dim d (model width)
n_head = 4               # attention heads
n_layer = 4              # stacked transformer blocks
dropout = 0.1
device = "cuda" if torch.cuda.is_available() else "cpu"
torch.manual_seed(1337)

# ---- 1. DATA + char-level tokenizer ----
with open("input.txt", "r", encoding="utf-8") as f:
    text = f.read()
chars = sorted(set(text))
vocab_size = len(chars)
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for i, c in enumerate(chars)}
encode = lambda s: [stoi[c] for c in s]
decode = lambda l: "".join(itos[i] for i in l)
data = torch.tensor(encode(text), dtype=torch.long)
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]

def get_batch(split):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size, (batch_size,))
    x = torch.stack([d[i:i + block_size] for i in ix])
    y = torch.stack([d[i + 1:i + 1 + block_size] for i in ix])  # targets = x shifted by 1
    return x.to(device), y.to(device)

# ---- 2. MODEL ----
class Head(nn.Module):
    """One head: softmax(Q.Kt / sqrt(d)) . V with a causal mask."""
    def __init__(self, head_size):
        super().__init__()
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))
        self.dropout = nn.Dropout(dropout)
    def forward(self, x):
        B, T, C = x.shape
        k = self.key(x); q = self.query(x)
        wei = q @ k.transpose(-2, -1) * k.shape[-1] ** -0.5    # scaled scores (B,T,T)
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))  # causal mask
        wei = F.softmax(wei, dim=-1)
        wei = self.dropout(wei)
        return wei @ self.value(x)                              # weighted sum of values

class MultiHeadAttention(nn.Module):
    def __init__(self, num_heads, head_size):
        super().__init__()
        self.heads = nn.ModuleList([Head(head_size) for _ in range(num_heads)])
        self.proj = nn.Linear(n_embd, n_embd)
        self.dropout = nn.Dropout(dropout)
    def forward(self, x):
        out = torch.cat([h(x) for h in self.heads], dim=-1)
        return self.dropout(self.proj(out))

class FeedForward(nn.Module):
    def __init__(self, n_embd):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_embd, 4 * n_embd), nn.ReLU(),
            nn.Linear(4 * n_embd, n_embd), nn.Dropout(dropout))
    def forward(self, x):
        return self.net(x)

class Block(nn.Module):
    def __init__(self, n_embd, n_head):
        super().__init__()
        head_size = n_embd // n_head
        self.sa = MultiHeadAttention(n_head, head_size)
        self.ffwd = FeedForward(n_embd)
        self.ln1 = nn.LayerNorm(n_embd)
        self.ln2 = nn.LayerNorm(n_embd)
    def forward(self, x):
        x = x + self.sa(self.ln1(x))     # residual around attention
        x = x + self.ffwd(self.ln2(x))   # residual around feed-forward
        return x

class GPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.token_embedding_table = nn.Embedding(vocab_size, n_embd)
        self.position_embedding_table = nn.Embedding(block_size, n_embd)
        self.blocks = nn.Sequential(*[Block(n_embd, n_head) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size)
    def forward(self, idx, targets=None):
        B, T = idx.shape
        tok_emb = self.token_embedding_table(idx)
        pos_emb = self.position_embedding_table(torch.arange(T, device=device))
        x = self.ln_f(self.blocks(tok_emb + pos_emb))
        logits = self.lm_head(x)
        loss = None
        if targets is not None:
            B, T, C = logits.shape
            loss = F.cross_entropy(logits.view(B * T, C), targets.view(B * T))
        return logits, loss
    @torch.no_grad()
    def generate(self, idx, max_new_tokens):
        for _ in range(max_new_tokens):
            logits, _ = self(idx[:, -block_size:])
            probs = F.softmax(logits[:, -1, :], dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
            idx = torch.cat((idx, idx_next), dim=1)
        return idx

# ---- 3. TRAIN ----
model = GPT().to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=learning_rate)
for it in range(max_iters):
    xb, yb = get_batch("train")
    logits, loss = model(xb, yb)
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()

# ---- 4. GENERATE ----
context = torch.zeros((1, 1), dtype=torch.long, device=device)
print(decode(model.generate(context, max_new_tokens=500)[0].tolist()))
